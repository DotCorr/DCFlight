# Generated iOS camera and map mechanics

The routed backend emits ordinary `NativeDevice.swift` using AVFoundation, CoreLocation and MapKit. All camera/map controls, labels, permission purpose strings, flow destinations, map regions and annotation content are authored in the shared application. The compiler adds authored camera/location descriptions to a generated Info.plist and references it from a newly generated Xcode project. Existing user-owned project files retain their ownership; changes to custom project configuration require explicit reconciliation.

Camera permission is requested only by PermissionEffect. CameraPreview never requests permission itself. Native capture hardware runs only when the authored active state is true and the preview is visible in an active scene. Disappearance/background stops it. The readiness binding reports actual session state. The preview's scene orientation is applied to both the preview layer and capture connection. Facing is an explicit front/back effect. Capture outputs the existing transient media value after the same authored normalization bounds; no native send/upload/story rules exist. Each photo callback must match the exact native capture settings ID, preventing a cancelled capture from completing a subsequent one. Physical camera capture and rotation still require hardware verification.

One-shot location has its own native manager for each read. Cancellation detaches that manager's delegate, and callbacks must match the active manager identity. A returned sample must be at least as recent as the read's start; old cached or cancelled-request results cannot complete a new read. The authored timeout bounds the request. Latitude/longitude are nearest microdegrees with half ties away from zero; nonnegative accuracy rounds up to whole meters. Outputs assign atomically only after validating coordinates and accuracy. The location effect performs no publication, consent decision or server call. Explicit Cancel invalidates callbacks; timeout and unavailable fixes route to authored failure.

MapKit receives the authored region and typed collection records. Annotation UI is the authored text/icon/row/column/card subtree hosted as native annotation views, including styles and field bindings. Native annotation IDs are stable collection keys; unchanged markers update in place. Authored selection supplies the selected key and flow callback. MapKit's loading/failure events show the authored child content. Dynamic markers outside the shared Mercator latitude limit of ±85,051,128 microdegrees or geographical longitude range reject the entire map state into the authored failure view. Location readings retain the wider geographical ±90° latitude range. MapKit supplies its own provider and attribution; Android's explicitly locked MapLibre module/style configuration is not silently used as an iOS provider.

## Evidence and limits

`tests/test_ios_device.py` checks emitted permissions, manifest linkage, scoped annotation content, cancellation guards and fresh native SDK compilation. `tools/verify_ios_device.py` executes native simulator helpers without foreground UI or permission prompts and reports source/fixture/binary hashes. Checks cover coordinate rounding/bounds/accuracy, old and fresh sample timestamps, authored map region, actual annotation hosting and dimensions, simulator camera unavailability, inactive capture and unavailable-facing failures.

These checks do not prove physical camera operation, real GPS/permission interaction, map tile network availability or end-to-end map UI. Those require distinct execution evidence. No framework runtime or graph interpreter is introduced; the helper sources are generated application-owned native source.

### Native map loading evidence

`tools/verify_ios_map_load.py` compiles the generated native helpers with a signed simulator fixture and asks `MKMapSnapshotter` to render the authored world region. The live SDK run rendered real land, ocean and map labels, including Apple Maps attribution. Its report records logical point dimensions separately from PNG pixel dimensions. This is native map-loading evidence, not an inspection of the product Map tab, annotation interaction, or physical-device performance. The fixture sends no UI input.
