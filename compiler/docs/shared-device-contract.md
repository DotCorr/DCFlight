# Shared camera, permission, location and map authoring

All product screens, text, styling, destination choices, consent and service calls remain in the shared Dart app. `device_ir.py` represents native operation inputs/results at development time; it is not shipped as a runtime registry. Existing released DC Dart 0.1.1 compiles the sample's readiness/consent/accuracy rules to native objects.

`CameraResource(id)` declares one native camera lifetime. `CameraPreview` binds an authored Boolean `active` state and a separate writable Boolean `ready` state, explicit fit/fill and accessibility text. Its two children are authored loading and failure states. It adds no permission request, shutter, flip control, routing or application copy. A disposed/background preview must close hardware even when its authored active flag remains true. Reappearing may resume only while active and OS permission remains granted.

`PermissionEffect(capability, statusTarget, success, failure)` is explicit. Capability is camera or location. An authored `permissionDescriptions` entry generates the iOS purpose string; no implicit photo-library permission accompanies a system picker. Result codes are 1 granted, 2 denied, 3 restricted, 4 unavailable. Only granted invokes success. `CameraFacingEffect` chooses explicit front/back and reports unavailable devices; `CapturePhotoEffect` writes an already declared transient media target using the same bounded `PhotoOptions` as the picker. Native device failures or stale callbacks cannot manufacture successful captures.

`LocationEffect` performs one foreground sample, atomically assigning integer latitude/longitude microdegrees and accuracy rounded up to whole meters to three distinct Int32 states. Timeout is authored, 250–60000 ms, default15000. Native adapters reject invalid coordinates/accuracy. This effect does not request consent, publish coordinates or pick a freshness policy. Explicit `CancelEffect` invalidates pending work and drops stale completion; it does not invoke an old account's cancellation flow. A native cancellation still in a valid operation scope may invoke the declared cancel flow. Timeout/unavailability invoke failure.

`NativeMap` references a typed collection and integer latitude/longitude fields plus a string title field. `MapRegion` gives authored center and full spans in microdegrees. The shared map latitude range is ±85,051,128 microdegrees (Mercator); location samples retain the geographic ±90-degree range. Spans crossing that map latitude cap or the antimeridian are rejected rather than silently normalized, and out-of-range dynamic markers must fail the map visibly. Coordinate rounding is nearest, ties away from zero on both targets. Accuracy rounds up (ceiling) to avoid understating uncertainty. Optional selection uses the collection key and an authored flow; both must be supplied together. Children are annotation, loading and failure, in that order. Annotation primitives are text, icon, row, column and card, with scoped field references and supported styles. Interactive actions and motion are rejected. Each native implementation compiles this authored annotation into native views; Android may draw those generated Compose views into map marker images. There is no runtime IR evaluation or dcflight renderer.

The iOS provider is native MapKit. Android uses the declared content-locked MapLibre native module. `MapConfig(androidModule, styleUrl, attribution)` explicitly supplies its style/provider attribution, which must remain visible. The sample references its existing module lock without duplicating the dependency archive set and uses the approved OpenFreeMap Liberty style. Provider SDKs are ordinary generated-project dependencies; they do not change the prohibition on a dcflight runtime.

The shared sample has Camera, Chat, Stories, Map and You tabs, with People inside Chat. Camera currently captures photos for stories; conversation photos can be selected from the library. Location is shared only after an explicit button, OS grant, native sample and shared DC Dart consent/accuracy decision. Stop sharing cancels pending sampling immediately and separately requests server removal; failed removal has explicit authored copy explaining the previous location's one-hour expiry.

Map responses include their earliest record expiry, assigned atomically with the collection. An authored clock and compiled DC Dart deadline decision clear the entire cached collection at that deadline and require refresh, so expired coordinates do not remain displayed indefinitely.

SDK compilation and simulator unavailable-camera checks do not establish physical camera capture, rotation or lens switching on hardware. Native helper and generated-model reports identify their actual scope. Private-photo view lifecycle, camera background shutdown and map interaction require their native tests; source validation alone does not prove them.
