# Narrow native media and location adapters: proposed next shared contract

Status: design audit, not implemented in the routed compiler. The legacy social templates provide reusable implementation evidence, but must not supply application screens, copy, routing, endpoints, or sharing policy. The 91-node shared Chat/People/You app now builds and launches independently of those templates.

## Minimum typed additions, in dependency order

1. **Transient media state.** `MediaState(name)` emits an optional native value containing encoded bytes and trusted decoded metadata; it is not a string file path, base64 JSON value, or persisted state. Native iOS representation can be `PreparedMedia(data: Data, mimeType: String, width: Int32, height: Int32)`. Expose typed `mediaByteLength`, width/height and presence projections to shared policies. A clear-media effect releases data and invalidates pending acquisition; logout clears private media as well as collections. Do not make the response registry executable.
2. **Named native operation results.** Every acquisition has explicit success, cancellation and failure flow IDs and typed output targets. Use compiler-known error/permission enums (with documented integer ABI codes for DC Dart), never localized exception text as application copy. Completion validates all outputs before assignment and ignores callbacks after cancellation, route disposal or account change. Media/camera/location operation scopes must be distinct from the existing single HTTP request generation counter.
3. **Photo acquisition and normalization.** `PickPhotoEffect(target, success, cancel, failure)` invokes the system single-image picker. `PreparePhotoEffect(source, target, maxEdge, jpegQualityPercent, success, failure)` runs native bounded decode/re-encode off the main actor, strips metadata and reports typed dimensions/byte length. Acquisition must impose input byte/pixel/frame bounds before decoding; reject unsupported animated/video content explicitly. Shared DC Dart decides upload acceptance using returned byte length. The normalizer itself must not call Snap policies.
4. **Camera resource and effects.** `CameraResource(id)` plus `CameraPreview(resource, contentMode)` and explicit `CameraEffect(resource, operation, outputs, success, failure)` operations start, stop, capture and setFacing. Start returns typed permission/availability state; capture targets transient media; setFacing takes an authored enum, not a hidden toggle. Preview contains no shutter button, messages, navigation or upload. Stop is idempotent; a noninteractive/disposed scene must release camera hardware even if a shared callback is cancelled.
5. **Binary network body and authenticated image.** Extend typed request body to a disjoint JSON-object or `MediaBody(mediaRef)` union; content type comes from trusted prepared media. Keep existing typed JSON response outputs and authored request paths/status flows, so upload `/v1/media` and subsequent story/message POSTs remain normal shared declarations. `MediaImage(source, loadingChild, failureChild, accessibilityLabel)` accepts either a transient media reference or explicit authenticated remote source (transport, PathTemplate, bearer reference, response bounds). Authenticated bytes must not use public AsyncImage URL cache; clear decoded pixels on token/source change, logout, expiry or disposal. Do not hardcode the `/v1/media` endpoint in this adapter.
6. **One-shot location and native map.** `LocationEffect(operation: request|cancel, latitudeE6, longitudeE6, accuracyMeters, permissionTarget, success, failure)` emits native CLLocationManager calls and bounded numeric conversion. A generic `Map(collection, keyField, latitudeField, longitudeField, annotationChild, viewport)` emits MapKit annotations from typed collection records; annotation child uses the same scoped FieldReference mechanism as Repeat. Validate latitude/longitude ranges and reject invalid samples. It does not request permission, publish data, decide consent, impose an expiry, or call a server.
7. **Generic view lifecycle and timed flows.** Authored appear/disappear/foreground/background action IDs and a scoped `Timer(interval, action)` are needed for camera lifecycle, map refresh, and open-story expiry. Timers cancel when their owner disappears; camera/location adapters still enforce native resource shutdown independently. Add an explicit clock effect and sufficiently wide timestamp type: current Int32 JSON states cannot represent epoch seconds beyond2038. Never silently truncate. Shared DC Dart owns expiry and publish-consent policies; selected story content must also stop rendering at expiry.
8. **Shared overlay and event primitives.** A generic overlay/stack with authored alignment expresses the camera and map controls without whole-screen native templates. A generic button with an authored child can compose shutter and icon controls. Toggle onChange and route appearance actions should target the same typed flow action space. Privacy purpose strings belong to authored platform configuration, generating Info.plist declarations; there must be no hidden default Snap privacy copy.

## Smallest usable migration sequence

Implement transient media → picker/normalizer → raw upload request → local/authenticated image first. Those additions allow a fully shared photo composer and photo messages using the already implemented routes, scalar states, collections and flow chains. Add camera preview/effects next, keeping the same composer. Add clock/lifecycle plus shared story list/view/delete. Finally add one-shot location/map surface and author consent/publication/refresh in the same shared app. Existing native MapKit and AVFoundation mechanisms do not justify bringing back platform-specific screens.

## Required verification before claiming support

- Generate both platforms from the same mutated authored copy/layout/actions; no feature screen or endpoint strings in adapters.
- Compile real picker/camera/map surfaces against installed native SDKs. Check actual camera rotation and lens switching on hardware; simulator unavailable-camera evidence is insufficient.
- Exercise native photo decode with orientation/EXIF/GPS, malformed and over-limit inputs, animated media, cancellation and rapid reselection. The existing legacy fixture's24 checks are reusable test ideas, not certification of new adapters.
- Execute raw upload/download with bearer authentication, redirect rejection, bounded streaming and metadata checks against the real server; wrong auth must never reuse prior decoded image pixels.
- Execute consent-off, permission-denied/revoked, stale location, background/disappear, logout during acquisition and clock-driven open-story expiry paths. Verify transient/private state clearing and no stale callback publication.
- Audit final binaries and generated project dependencies for the existing no-dcflight-runtime rule.

No IR or backend implementation files were changed by this audit.
