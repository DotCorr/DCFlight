# Runtime audit identity and evidence scope

The source audit reads the application identifier from the local generation input receipt. Exact self-qualified identifiers in code and applicationId/namespace/bundle-identifier fields are application identity, not a framework dependency. Bundle display names, app-name XML resources and noninterpolated literal Text/setText/navigationTitle labels are data positions. Comments do not establish runtime dependencies. Imports, dependency coordinates, other string values, runtime API identifiers and recognizable dynamic loading strings remain inspected. A local receipt is not a signed attestation; generated-file integrity is checked separately.

The APK audit accepts `application_id=` as an explicit caller-supplied identity (use the authored/verified application ID). It parses bounded standard little-endian DEX string/type/class tables instead of scanning all raw bytes for words. It inspects both definitions and referenced runtime namespaces, plus recognizable module/class/library strings. The application's own exact namespace is excluded, with remaining class/member components still checked. The dcflight runtime namespace and known third-party engine namespaces cannot be exempted by choosing their namespace as an application ID.

AndroidX may refer to platform `android.webkit` classes without bundling or activating an engine. Those references are reported as `platformWebTypeReferences`, not counted as bundled engine code. Definitions under that namespace are rejected. Source usage/import checks still reject authored WebView APIs. Generic prose or a generic string such as `v8` does not prove dynamic engine loading. Recognizable `libdart.so`, `libhermes`, `dcflight.Runtime` and similar strings remain rejected; source-level loadLibrary/dlopen/forName calls also inspect short engine names.

Exact expected native library names and SHA256 hashes remain mandatory. Known engine-library names reject even if present in the expected hash map. Dart/JS/WASM/dill/snapshot payload extensions reject regardless of case. These checks are defense in depth: opaque dynamic loading, reflection assembled at runtime, renamed/obfuscated code and arbitrary native-library behavior require build/link/runtime review; no static audit claims they are impossible.

Bounds:16MiB source input,128MiB per DEX,1million table entries,1MiB individual DEX string,128MiB aggregate decoded string bytes,65536 APK entries. Unsupported/malformed DEX headers, table ranges, indexes and unterminated strings reject. Real Compose metadata includes strings larger than64KiB, so the measured fixture required the explicit1MiB individual-string bound.

Regression evidence retains the original QA failed audit unchanged. The staged scanner passes those same generated bytes and the exact previously built dev26 Android APK (13,082 defined classes), without altering the compiler output, signed app, original account data or device state.
