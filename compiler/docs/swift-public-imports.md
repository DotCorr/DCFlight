SDK symbol ownership and the public import entry point are different facts. The installed iOS26.2 SwiftUICore and RealityFoundation interfaces declare -public-module-name SwiftUI and RealityKit respectively. Their public umbrellas re-export these implementation modules; native Swift6 diagnostics explicitly reject importing the implementation modules directly.

The compiler maps those two reviewed names to their public entry points when collecting emitted imports, including per-symbol bystanders. Symbol IDs, owning module, type resolution provenance, declaration types and availability remain unchanged. Unknown names are left exact; arbitrary symbolgraph metadata cannot install an alias. Imports are sorted and deduplicated. This is development-time source generation and adds no runtime dependency beyond the selected native frameworks.

The same mapping is used by ordinary NativeAPI calls, assignments, sequence/operation emitters consuming those calls, and native verification through Emission.imports. Automatically selected type-graph imports and explicitly selected verifier modules use the same reviewed public-entry mapping before candidate source/receipt generation. This prevents an internal type-graph module from reintroducing an invalid direct import. Missing parameter-type dependencies and unsupported signatures are separate and are not silently added by this mapping.

Native evidence retains unmodified original SDK graphs and compares generated probes against the same dev22 inputs. It is native typechecking only, not execution or general framework coverage. The narrow allowlist can be extended after checking SDK public-module-name metadata, exported imports and native compiler behavior; underscores alone are not a routing rule.
