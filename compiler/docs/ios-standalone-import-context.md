# Standalone native import context

An SDK conformance probe can explicitly import dependency modules. Those imports are part of the verified call, including explicitly authored additional imports. Automatic `--type-module` imports are selected per call by exact type references; extension receiver modules come from identity-bound SDK extension metadata. A partial graph with no matching nominal does not imply an import; supply an explicit `--import` if that extra context is intentional. Exporting a successful descriptor now retains that candidate's effective imports in `requiredImports`, in addition to its original graph-derived imports. The declaring module remains implicit. Original type-resolution module names and graph provenance stay intact; emission can normalize known public Swift module aliases separately.

Before creating any export output, each successful descriptor is reconstructed through the single-record `SDKCatalog.from_records` authoring path. Its emitted candidate, imports and exact generic specialization must reproduce the verified candidate without helper catalogs or additional imports. Invalid descriptors, oversized import sets or changed standalone emission fail export before files are written.

This preserves a native compilation context; it does not prove device execution, permissions, runtime availability or all generic instantiations. All other descriptors also retain the explicitly supplied imports and their exact resolved type/extension context without gaining native credit. This preserves future-target authoring for typed availability skips, without depending on unrelated global type-module imports. Failed and skipped declarations gain no native credit. Existing typed target-availability skips still retain their canonical availability contract.

Regression evidence uses unchanged retained ActivityKit SDK graphs and a byte-identical Foundation extension graph as a supported partial type-module input. `ActivityUIDismissalPolicy.after(Date)` previously passed its probe with Foundation imported but failed standalone public `NativeAPI` emission with only ActivityKit imported. The corrected exported record retains Foundation and the same ordinary Swift source typechecks when Foundation is explicitly imported or its exact referenced nominal is provided. No runtime dependency or platform source rewriting is introduced.
