An iOS-version skip is now distinct from structural unsupported status. SDKCatalog raises TargetAvailabilityError only when the requested iOS version violates an introduced/obsoleted interval. The exception carries a typed constraint, target and boundary; unconditional unavailability and obsolete Swift spelling remain ordinary rejections.

The native verifier records this typed classification. Export re-emits the same SDK candidate at the report target and requires the exact typed exception/classification before preserving canonical structural emittability and availability. It records nativeConformance.status=target_unavailable with the original target/diagnostics and no compiled credit. Missing, forged or unmatched classifications cannot make an API available. Unclassified skips, actor/generic/ownership failures and native failures remain closed. Generic owner descriptors remain unbound; preserving a version interval never grants general specialization support.

Public NativeAPI still runs SDK availability checks against the author's requested deployment target. Thus a valid iOS26 declaration exported from an18.0 sweep rejects an18.0 call and can be authored for26.2. This is source-level availability, not a claim the18.0 sweep compiled the26.2 call. Apps must use the actual authored target and platform compiler. Selected class-fact availability enters the same check after specialization.

Native proof uses unmodified selected symbols from the retained UIKit26.2 SDK for UITraitResolvesNaturalAlignmentWithBaseWritingDirection.defaultValue. After18.0 verification/export and a public Catalog/NativeAPI roundtrip,18.0 authoring rejects;26.2 authoring emits ordinary Swift. The same generated source typechecks at26.2 and fails native typechecking at18.0; the fixture receives zero18.0 compiled evidence. No authoritative catalog or application is changed.

Existing reports remain bound to their original compiler fingerprint. Re-run verification under the corrected final release before exporting; do not edit fingerprints or relabel historical skipped evidence. This change does not solve actor-context-specific native rejection, generic witness selection or unavailable accessor contracts. Those require separate exact-context proof.
