# Replayable Android native version requirements

`NativeAPI.emit` and native sequences accept paired positive base integers no greater than999 `androidMinSdk` and `androidCompileSdk`. `NativeImplementation` exposes the same pair in Dart and JSON. An explicitly supplied pair requires exact known availability. A routed application's canonical Android configuration supplies its minimum and compile SDK to every selected Android operation, including calls where the operation omits these fields. An explicitly higher operation floor or different compile SDK is rejected. There is no implicit runtime guard.

SDK imports with `--api-versions` now retain the exact `javap -public -s` declarations alongside normalized source and schema3 XML. Emission reopens bounded content-addressed snapshots, checks their hashes, reconstructs the declaration-to-JVM association, and recomputes XML requirements. Full normalized declaration identity distinguishes covariant bridge returns. Stored descriptor availability must equal the recomputed facts. Previously imported XML without this retained declaration evidence remains unverified and requires reindexing for strict use.

Known base requirements are checked even when `validateNativeAvailability` is false. False permits unknown facts with an explicit `versionAvailability.status=unknown`; true rejects them. Successful checks report `base-version-checked`, never runtime-supported. A finite removal rejects an unguarded call because targetSdk is not a maximum runtime OS. An explicit SDK0 branch contributes its base floor; extension-only entries stay unknown and reject strict validation. Extension alternatives, permissions, flags, nullability and thread requirements are not certified here.

The configured compile SDK must equal the captured SDK level. Accepted calls add the captured SDK archive hash to the ordinary generated Gradle build's SDK guard. It checks the actual bootclasspath JAR, alongside the separate authored-version Gradle hook. Conflicting SDK hashes reject. These scripts and the compiler remain development-time inputs; no SDK archive or dcflight runtime is added to the app.

Snapshot hashes establish consistency with retained import inputs, not cryptographic publisher authenticity. The catalog and original SDK acquisition remain trusted developer inputs. No physical device execution is inferred from a successful native build.
