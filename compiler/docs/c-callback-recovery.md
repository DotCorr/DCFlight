# Explicit C callback convention recovery

Some Swift symbol graphs omit `@convention(c)` from callback parameters imported from C. A plain Swift closure type is not interchangeable with a C function pointer. The development-time recovery tool writes an explicit derived graph; it never patches an SDK, introduces app runtime support, executes a selected C function, or marks the resulting API native-verified.

Run `python tools/recover_c_callbacks.py --graphs PATH --module Darwin --id 'c:@F@err_set_exit' --output NEW_DIRECTORY`. The default compiler and simulator SDK are located through Xcode; explicit `--swiftc`, `--sdk`, and `--target` are available. Later compilation must use the matching native toolchain/SDK and normal native verification. This checkout helper also imports only packaged dcflight modules; it has no dependency on other tools modules.

The bounded first contract accepts 1–16 explicitly named global functions with exact `c:@F@NAME` identities. It checks the graph kind, owner module and simple global name, emits an import and one value binding, and runs Swift 6 `-dump-ast`. It reads exactly one actual `declref_expr`; compiler-inserted conversion types, including an inferred outer `@Sendable`, are never used as callback evidence. Its declaration must identify the selected module/function and an existing header below the selected SDK root. The exact reported header line and UTF-8 byte column must point to that function token.

The complete native function type is parsed using the existing typed Swift grammar. Parameter count, result type, optionality, callback parameter/result types, effects and attributes must match the graph exactly except for adding `convention(c)` to an outer callback parameter. New Sendable, actor, escaping, ownership, nested callback or type changes are not inferred. Unsupported or ambiguous AST/type forms fail closed.

The same captured graph bytes are hash-checked, decoded, retained and imported; encoded and expanded snapshot totals each have a 512MiB bound. Original compressed graph bytes are retained under `original/`; the derived graphs remain ordinary explicit JSON files. The bundle records probe source, AST, commands, header path/line/hash, Swift driver and frontend binary hashes/version, SDK settings hash, deployment target, all compiler source hashes, original/derived graph hashes, and exact parameter changes. Native inputs are checked again before completing the manifest. The report is version-bound provenance, not an authenticity certificate for externally supplied compiler binaries or graph files. There is no implicit sidecar lookup during app compilation.

All unrelated descriptor metadata must compare equal after reimport. This intentionally fails closed if graph-source changes alter unrelated source-bound class facts. Wider source-metadata composition needs an explicit future contract rather than deleting provenance to make comparisons pass.

The initial bounded SDK proof covers Darwin `err_set_exit` and CoreMedia `CMBufferQueueCallForEachBuffer`. For each, the ordinary generator's original call fails Swift 6 typechecking while its derived call passes with the recovered C callback type. No selected C function is executed. This proves these two generated signatures in one SDK/target context, not all callbacks or platform coverage. Independent tests reject changing parameter/result types, optionality, Sendable, nested-only conventions, AST identity and header location.

Output ancestors use the existing strict symlink policy, permitting only verified root-owned macOS temporary-directory aliases. Native tool processes run in an isolated process group; timeout and all other exits stop and wait for that group, including a delegated Swift frontend. Regression tests include a spawned writer which must stop after timeout.
