Native SDK conformance reports now use `dcflight.ios.import-contract.v2`. Every candidate is generated through one helper shared by native verification and export replay. Its effective imports are the actual emitter imports plus explicitly requested additional/type-module imports. Candidates are compiled only with others having the identical sorted import set. A module required by one overlay can no longer silently make another candidate compile.

Reports retain each candidate's source/imports/specialization, and each actual native attempt's exact command, command SHA256, import set, member identities, source SHA256 and exit status. Failed attempts remain in the report; only members of a successful compiler invocation become passes. Export rebuilds candidates from the current compiler and exact graph inputs, checks all these import/source/command contracts, and requires successful invocations to correspond exactly to reported passes. This verifies reproducibility and hash continuity; it is not a signature authenticating arbitrary caller-provided reports or a runtime execution claim.

Old-format reports remain historical artifacts. New export rejects them with a regeneration message; do not relabel old evidence v2 or transfer passed status across altered compiler/graph/import identities. Explicit additional imports still apply to all requested candidates by author instruction; inferred emitter imports remain candidate-specific. The bulk verifier continues using Swift MainActor context; other actor contexts require separate exact invocation evidence.
