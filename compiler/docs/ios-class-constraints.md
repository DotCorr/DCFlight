# Explicit SDK class-constrained generic receivers

Some Apple symbol graphs preserve a nominal declaration such as `class PHFetchResult<ObjectType> where ObjectType : AnyObject` while omitting that requirement from `swiftGenerics.constraints`. The compiler intersects structured constraints with declaration requirements. Unsupported requirements, missing parameter identities, dependent bounds and unresolved syntax block the affected generic owner rather than dropping its restrictions. Existing identity-bound single-pack receivers remain supported.

`AnyObject` requires an indexed class argument. Generic descriptors carry optional `ownerClassFacts`: exact nominal identity, source module, class kind, spelling, declaration availability and contributing graph SHA256. This survives the normal registry record serialization, so a single descriptor loaded through NativeAPI supports explicit `PHFetchResult<PHAsset>` or `CNFetchResult<CNContact>` receivers. Both unqualified source-module names and qualified names such as `Photos.PHAsset` are accepted. No user source string is executed or inferred to be a class.

The bounded implementation indexes at most128 class facts from the descriptor's own source module. Only top-level nongeneric class nominals participate. Structs, protocols, actors, optional types, metatypes, unknown classes, generic class arguments, unresolved superclass/protocol constraints, and classes outside their declared deployment availability remain rejected. Multiple source facts for the same class retain all contributing availability restrictions. Source-module imports are unchanged.

A source module exceeding128 facts is still imported. Only affected class-constrained generic descriptors receive an explicit unsupported reason; facts are never arbitrarily truncated and nongeneric APIs are retained. Broader class indexes and cross-module class arguments need a separate bounded indexed-proof contract. The limit must not be described as full generic coverage.

Native verification chooses an available source class witness only for parameters actually constrained to AnyObject. Unconstrained/scalar-constrained parameters retain their previous witness strategy, and all other generic constraints are checked before emission. Successful reports record the exact specialized receiver. They do not make an unbound generic descriptor generally emittable or generally compiled.

Validation includes public NativeAPI and sequence calls from a catalog containing only one generic descriptor; explicit PHAsset/CNContact native Swift6/iOS18 typechecks; rejection of Int; class-availability checks; malformed metadata and restricted-record rejection; an executed native class-bound fixture; and paired UIKit/Foundation regression sweeps against identical frozen-baseline inputs.
