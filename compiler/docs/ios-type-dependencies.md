# Exact SDK type dependencies

`python tools/plan_ios_type_dependencies.py --capture RETAINED_EXTRACTION --module RealityFoundation --output FRESH_DIRECTORY` scans verified retained SDK symbolgraphs and derives type-module graphs containing only nominal declarations whose exact `preciseIdentifier` occurs in the primary declaration/signature fragments. Repeat `--id` to restrict planning to named primary symbols. Text spelling is never used to identify a type.

The output retains exact original compressed/raw source bytes, primary graph copies, explicit derived nominal subsets, graph and normalized-symbol hashes, capture context, unresolved identities and module paths. Each derived nominal is an unchanged SDK symbol object. Unrelated nominals are excluded to avoid unrelated cross-import collisions. Conflicting module/kind/spelling for a wanted identity fails. Conflicting duplicate declarations in one source fail; matching identities across source graphs preserve their availability-bearing declarations. Missing nominal identities remain explicit; associated types and absent modules are not guessed.

Pass `MODULE=OUTPUT/types/MODULE` as `--type-module` arguments to the native verifier, with `--module PRIMARY=OUTPUT/primary`. The ordinary verifier and exporter validate the graphs and resulting native evidence. This planner grants zero native credit and does not change any catalog. After planning, graph modifications produce different verifier hashes; the planning manifest is provenance, not a signed authority or permission to skip native checks.

The planner rejects mixed SDK contexts, corrupted encoded/raw graph hashes, changed input snapshots, unsafe output symlinks and existing destinations. Publishing is a fresh-directory rename after successful planning; failure leaves no published bundle. Limits: 512 modules, 4,096 graphs, 512MiB per expanded graph, 4GiB aggregate expanded scan, 16,384 referenced identities, 32 dependency modules and 512MiB retained output. A large app can request smaller explicit identity subsets. The helper is development-time tooling only and adds no shipped code.

For simulator/device evidence, captures must share the exact environment and target. This helper does not add environment support to structured application authoring. Signing, runtime behavior and hardware availability remain separate from native compilation.
